📋 Repository Overview

Purpose

Apha.BatchJobs is an independent microservice that provides batch job orchestration and execution for the FPS application suite. It consists of both an API layer for triggering/status management and a Worker layer for background job execution.

Key Characteristics

  • .NET 10 (LTS) + ASP.NET Core microservice
  • PostgreSQL 16 for persistence
  • Docker containerization
  • AWS ECS deployment target
  • Dual entry points: API + Worker
  • GitHub-based CI/CD automation

🐳 Docker & Container Strategy

Base Images

Stage Base Image Purpose
Build mcr.microsoft.com/dotnet/sdk:10.0 Build and publish .NET application
Runtime mcr.microsoft.com/dotnet/aspnet:10.0 Production runtime (reduced size)

Dockerfile Strategy

  • Multi-stage build: Minimizes final image size
  • Non-root user: Runs as batchjobs:batchjobs (UID 10001)
  • Security headers: LABEL tags for governance and metadata
  • Environment setup: Production mode, no development files
  • Health considerations: Linux glibc libraries for Kerberos support

Docker Compose (Local Development)

  • Profiles supported:
    • withdb - App + PostgreSQL 16
    • nodb - App only (in-memory repositories)
  • Usage:
    docker-compose --profile withdb up --build docker-compose --profile nodb up --build
  • Database: PostgreSQL 16-alpine with health checks
  • Network: Custom bridge network for service communication

Image Registry

  • ECR Repository: apha/batchjobs
  • Registry URL: <ACCOUNT_ID>.dkr.ecr.<REGION>.amazonaws.com/apha/batchjobs
  • Image Tagging Strategy:
    • :latest - Latest production release
    • :v<VERSION> - Semantic versioning
    • :<COMMIT_SHA> - Git commit reference
    • :main-<BUILD_NUM> - Main branch builds
  • Retention Policy: Keep last 20 images, delete after 90 days

🚀 CI/CD Pipeline Configuration

GitHub Actions Workflows

Workflow File Trigger Purpose
batchjobs-ci.yaml Push to feature/*, fix/*, docs/*, main Build, test, analyze, container build
batchjobs-scheduled-container-test.yml Scheduled (e.g., nightly) Periodic smoke tests + security scanning

Primary Workflow (batchjobs-ci.yaml) Pipeline

  1. Checkout: Clone repository with full history
  2. Setup .NET 10: Install runtime and SDK
  3. Restore dependencies: dotnet restore
  4. Build solution: dotnet build -c Release
  5. Run unit tests: PostgreSQL service available at localhost:5432
  6. Code analysis: SonarQube integration (SONAR_TOKEN secret)
  7. Build Docker image: Multi-stage build to apha/batchjobs:<tag>
  8. Check commit message: Look for "ecrpush" keyword
  9. Push to ECR: If "ecrpush" present in commit message

Test Services

Service Image Purpose
PostgreSQL postgres:16 Integration tests, smoke tests

Path Filters

paths: - 'src/Apha.BatchJobs/**' - '.github/workflows/batchjobs-ci.yaml'

Prevents: Workflow runs on unrelated changes (FPS, Costbook, etc.)

Scheduled Workflows

  • Container security scanning: Weekly or nightly
  • Integration testing: Against current main branch
  • Dependency updates: Check for NuGet vulnerabilities

🔐 Secrets & Credentials Management

Required GitHub Secrets

Secret Name Purpose Scope
SONAR_TOKEN SonarQube code quality analysis Repository
AWS_ROLE_TO_ASSUME AWS role ARN for ECR push (OIDC) Repository
AWS_REGION AWS region for ECR Repository (can be variable)

Environment Secrets in Workflows

env: ConnectionStrings__BatchJobsConnectionString: Host=localhost;Port=5432;Database=batch_jobs_foundation_db;Username=postgres;Timeout=30 BATCH_JOB_NAME: HealthCheck DOTNET_ENVIRONMENT: Development

Runtime Secrets (Production ECS)

Supplied via:

  • AWS Secrets Manager: Database credentials, API keys
  • ECS Task Environment Variables: Non-sensitive config
  • Parameter Store: Feature flags, endpoints
Do NOT store appsettings.Development.json in production image

☁️ ECR Configuration

Repository Setup

  • Repository Name: apha/batchjobs
  • Scan on Push: Enable (ECR Basic image scanning)
  • Encryption: Use default AWS managed key
  • Lifecycle Policy: See below

ECR Lifecycle Policy

{ "rules": [ { "rulePriority": 1, "description": "Keep last 20 images, expire others", "selection": { "tagStatus": "any", "countType": "imageCountMoreThan", "countNumber": 20 }, "action": { "type": "expire" } }, { "rulePriority": 2, "description": "Expire untagged images after 7 days", "selection": { "tagStatus": "untagged", "countType": "sinceImagePushed", "countUnit": "days", "countNumber": 7 }, "action": { "type": "expire" } } ] }

IAM Permissions

GitHub Actions OIDC role must have:

  • ecr:GetAuthorizationToken
  • ecr:BatchCheckLayerAvailability
  • ecr:GetDownloadUrlForLayer
  • ecr:BatchGetImage
  • ecr:PutImage
  • ecr:InitiateLayerUpload
  • ecr:UploadLayerPart
  • ecr:CompleteLayerUpload

✅ DevOps Implementation Checklist

Phase 1: Repository Setup (Day 1)

  • Create GitHub repository: apha-batch-jobs
  • Configure branch protection rules (main)
  • Add codeowners file (.github/CODEOWNERS)
  • Enable vulnerability scanning
  • Add required GitHub status checks

Phase 2: AWS Infrastructure (Day 2)

  • Create ECR repository: apha/batchjobs
  • Configure image scanning on push
  • Set ECR lifecycle policy
  • Create AWS OIDC GitHub identity provider (if not exists)
  • Create GitHub Actions assume role (IAM)
  • Attach ECR push permissions to role

Phase 3: CI/CD Configuration (Day 3)

  • Upload workflow files to .github/workflows/
  • Create GitHub secrets: SONAR_TOKEN, AWS_ROLE_TO_ASSUME, AWS_REGION
  • Test workflow trigger on feature branch
  • Verify build succeeds
  • Verify tests run with PostgreSQL service
  • Verify SonarQube analysis
  • Verify Docker image builds

Phase 4: Container Push Testing (Day 4)

  • Create test commit with "ecrpush" message
  • Verify GitHub Actions OIDC authentication
  • Verify image pushed to ECR with correct tag
  • Test image pull from ECR
  • Run container locally with environment variables

Phase 5: Documentation & Handoff (Day 5)

  • Document AWS resource IDs and endpoints
  • Create runbook for common DevOps tasks
  • Document troubleshooting procedures
  • Conduct team knowledge transfer
  • Archive setup documentation

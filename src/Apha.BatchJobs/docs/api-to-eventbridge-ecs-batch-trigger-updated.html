DB Shortcoming Log: MABArchive Strict-Year Isolation

Date: 2026-06-03

Issue: fps.qrytotaltestcosts did not expose fpsyear, which breaks strict year isolation checks for MABArchive totals rebuild.

Symptom: worker failed with: "Strict year isolation is enabled, but these fps source views are missing fpsyear: qrytotaltestcosts".

Local remediation applied:

CREATE OR REPLACE VIEW fps.qrytotaltestcosts AS
SELECT
    jobcode,
    SUM(notests * testprice) AS totaltestcosts,
    fpsyear
FROM fps.vtbltestrequ
GROUP BY jobcode, fpsyear;

Production action required: apply the same view definition through controlled DBA migration before release.

Rollout script: database/sql/2026-06-03-qrytotaltestcosts-add-fpsyear.sql

Post-fix status: strict-year-isolation check passes; next observed MABArchive blocker is a separate duplicate-key tracking/data issue and is not caused by this view shape gap.

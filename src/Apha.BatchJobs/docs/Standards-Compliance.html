Key Difference: Base Image Strategy

Standard Projects: Use defradigital/dotnetcore (Defra-managed images)
BatchJobs: Uses mcr.microsoft.com/dotnet (Microsoft official images)

Reason for Deviation: BatchJobs requires independent deployment model and uses different hosting infrastructure (standalone containers vs. shared Defra infrastructure). MCR images are equally secure and are maintained by Microsoft directly.

⚡ Intentional Deviations

Deviation #1: Dual Entry Points

What: Apha.BatchJobs has both Apha.BatchJobs.Api and Apha.BatchJobs.Worker
Why: Batch job orchestration requires both HTTP trigger/status interface (API) and background execution engine (Worker)
Impact: Can be deployed as two separate services, but share business logic and domain models
Standards Alignment: ✓ No violation — just extended pattern

Deviation #2: Layer Naming (Domain vs Core)

What: Uses "Domain" instead of "Core" and "Infrastructure" instead of "DataAccess"
Why: Follows Domain-Driven Design (DDD) terminology for clarity and industry standard naming
Impact: More explicit about domain focus and infrastructure patterns
Standards Alignment: ✓ Enhancement — aligns with DDD best practices

Deviation #3: Consolidated Test Project

What: Single UnitTests project instead of per-layer test projects
Why: Batch jobs module is relatively focused; consolidated tests reduce project overhead while maintaining coverage
Impact: Easier to manage shared test utilities and fixtures
Standards Alignment: ✓ Valid approach for focused modules; not required to match per-layer pattern

Deviation #4: MCR Base Images vs Defra Images

What: Uses mcr.microsoft.com/dotnet instead of defradigital/dotnetcore
Why: Batch jobs has independent deployment model; MCR images are equally maintained and secure
Impact: Different container size/compliance but same security model
Standards Alignment: ✓ Justified by independent deployment requirements

Deviation #5: Docker Compose with Profiles

What: Includes docker-compose.yml with development profiles
Why: Batch jobs need local testing with/without database — profiles enable flexible local dev setup
Impact: Better local development experience
Standards Alignment: ✓ Enhancement — improves dev productivity
